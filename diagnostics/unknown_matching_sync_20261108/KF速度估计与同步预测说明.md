# KF速度估计、unknown静止规则与车/障碍物同步预测

本次在上一版上补齐了unknown匹配中心的静止处理，仅修改kf_tracker.py。主链仍使用CV卡尔曼估计速度、实时Ackermann候选轨迹和同一时间轴的矩形碰撞检查。

## unknown的三个口径

| 用途 | unknown处理 |
|---|---|
| 匹配候选中心 | 固定为最近一次真实检测中心，不使用内部未确认速度平移 |
| 发布给规划/控制 | 速度0，中心/尺寸为最近实测框 |
| 规划未来占据 | 对所有未来时刻保持同一框，没有1.5m/s运动范围扩张 |
| 内部KF速度估计 | 连续位置观测继续更新vx/vy，用于以后确认真实运动 |

固定指当前预测内不运动；下一帧有真实检测时仍更新位置。关联搜索仍保留距离/测量误差门限，允许新检测的位置有变化。unknown不等于将内部速度估计每帧清零。

已确认静态物体匹配中心使用最后一次滤波观测中心。已确认动态物体匹配中心使用KF预测位置；前两帧漏检继续CV预测、第三个连续未匹配帧删除。

## 新ID怎样初始化速度

没有匹配到旧ID的检测创建KFTrack：

```text
state = [x_det, y_det, 0, 0]^T
P = diag(1, 1, 2, 2)
```

初速度vx=vy=0，同时速度协方差较大，表示尚不知道真实速度。不是随机设置速度，也没有根据pedestrian/vehicle等尺寸提示直接赋一个速度。

## 后续观测怎样更新速度

按真实点云采集时间间隔dt进行CV预测：

```text
F = [[1,0,dt,0],
     [0,1,0,dt],
     [0,0,1,0],
     [0,0,0,1]]
state_prior = F * state
P_prior = F * P * F^T + Q
```

实际测量只有中心位置z=[x_det,y_det]，H只选择状态的x/y分量。

```text
residual = z - H*state_prior
K = P_prior*H^T * inv(H*P_prior*H^T + R)
state_updated = state_prior + K*residual
```

虽然没有直接测量速度，F会在位置与速度之间产生协方差联系，K的速度行因此能够把位置残差转化为vx/vy的修正。速度是按连续观测、时间间隔和KF不确定性逐步估计的。

当前q=0.3，位置测量标准差r=0.15m（R=r²I）。更新后速度向量限制到1m/s以内。已确认动态输出speed=hypot(vx,vy)，运动heading=atan2(vy,vx)，几何框朝向通过独立shape_heading保存。

无匹配观测只predict，不做虚构update，也不靠预测帧累积动态确认次数。

动态确认需要连续5个匹配观测的内部速度>0.30m/s；静态确认需要连续10个匹配观测的内部速度<0.15m/s。新ID的学习过程可能使确认延迟超过5帧。特别慢的0.15–0.30m/s运动可能一直unknown；本次未修改阈值。

无噪声示例：10Hz，每帧沿x前进0.05m（真实速度0.5m/s），初始位置0，其他参数采用当前默认值：

| 时间s | 内部KF速度m/s | 发布速度m/s | 类型 |
|---:|---:|---:|---|
| 0.0 | 0.000 | 0.000 | unknown |
| 0.2 | 0.164 | 0.000 | unknown |
| 0.4 | 0.411 | 0.000 | unknown |
| 0.8 | 0.488 | 0.488 | pedestrian（已确认运动） |

以上是特定输入例子，不是固定确认时间。完整生成数值见explanation_examples.json。

## 规划怎样预测车

当前实车主链采样的是目标速度v与目标前轮转角δ，包含约9档速度、17档转角和当前/零值，不是任意独立的(v,w)组合。

转角和速度经加减速、jerk、转向速率/加速度、执行延迟约束后，每一步产生实际预测的v(t)、δ(t)：

```text
w(t) = v(t)*tan(δ(t))/0.69
```

以0.05s步长积分后轴自行车模型，得到每条候选的x/y/yaw；碰撞检查前转换为车体中心，检查完整1.2×0.8m车体。普通预测3s，已确认迎面避让至少5s。

## 障碍物是否在同一时刻预测

是。minimum_gaps()对每条小车候选的每个times[t]，计算该障碍物在同一时刻的框：

```text
动态：
  ox(t) = ox_stamp + vx*(age+t)
  oy(t) = oy_stamp + vy*(age+t)

unknown或已确认静态：
  ox(t) = ox_stamp
  oy(t) = oy_stamp
```

age是该次规划请求快照中障碍物消息的年龄。障碍物shape_heading保持，不把运动方向当成几何框方向。随后比较同一t下的车体框和障碍物框，减去采样间运动扫掠界，要求间距至少0.12m。

障碍物CV预测不依赖小车选择哪条候选；所有候选使用同一组障碍物未来位置，与各自小车未来位置按时间对应。

未来没有新观测，规划中只从KF最新状态做CV预测，不在未来每0.05s做新的测量更新。下一帧真实感知到达后，KF才更新，下一次规划重新计算。

同步时轴示例：小车当前车体中心x=0、速度0，目标v=0.5m/s、δ=0，包含当前速度/转向执行约束及0.1s延迟；障碍物消息中的x=2m，已确认向小车运动vx=−0.5m/s，消息年龄0.1s：

| 未来时间s | 小车中心预测x/m | 动态物体预测x/m | 若同位置物体为unknown，其预测x/m |
|---:|---:|---:|---:|
| 0 | 0.000 | 1.950 | 2.000 |
| 1 | 0.202 | 1.450 | 2.000 |
| 2 | 0.686 | 0.950 | 2.000 |
| 3 | 1.186 | 0.450 | 2.000 |

这是说明时间对应的候选轨迹，并不是一条已被允许执行的路径。动态物体靠近时，完整矩形会在同一时刻接近/相交，该候选将因碰撞检查不通过而被剔除。轨迹空间交叉需要结合双方通过时间和车体尺寸判断。

## 同步的范围

规划内部的预测时间轴一致。输入定位和点云并非严格同时采集：仍使用最近有效定位快照，动态障碍用消息年龄补偿；异步规划使用请求时快照，结果年龄上限0.8s，返回后监督器和50Hz控制器用最新位姿/障碍再做执行复核。因此“同步预测”不等于传感器严格硬件同步采样。

## 交付与验证

仅kf_tracker.py为本次修改的生产文件：新增association_position()区分静止匹配中心与内部KF估计，GlobalKFTracker.step()用该中心进行关联。规划时间检查没有另外改动。

回归86 passed、10 subtests passed、1保留的expected failure（首次未确认的迎面物体仍被按静止处理的既有负面案例）。记录的1683个检测帧完成对照，没有原始点云或真实ID/速度标注。新建轨迹1505→1527，平均unknown5.76→5.87，不能将其宣称为匹配准确率提升。
