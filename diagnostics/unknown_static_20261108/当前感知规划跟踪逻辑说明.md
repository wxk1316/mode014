## 1. 本次改了什么

用户要求：未确认障碍物按静止物体处理，去除任意方向 1.5 m/s 的运动假设。

- `unknown` 保留类别与 ID，但预测速度为零，预测中心固定于最后一次真实检测位置。
- 未确认目标的框使用最后一次真实测量的长、宽和形状朝向，不随漏检时间增长。
- 去掉规划中的 unknown 运动范围扩张，以及 unknown 专用的 0.4 s 动作/刹车范围分支。
- unknown 和已确认静态物体一起进入静态可见性引导，按完整规划时域检查物理碰撞。
- 去掉仅因 unknown 出现就进行的“可能迎面运动”侧移准备。
- 规划、执行复核、自转复核、自适应预瞄都使用同一固定框策略。即使旧消息给 unknown 携带非零速度或 `uncertainty_speed=1.5`，碰撞预测也忽略这些运动字段。
- 内部 KF 仍然估计速度。真实物体运动被确认后，才切换至动态 CV 预测和动态避让。

`obstacle_max_speed: 1.5` 仍然存在：用于匹配时的最大可达位移，以及已确认目标发布速度的上限；不再用于 unknown 的运动预测。已确认迎面目标的侧方引导距离也有 1.5 **米**，它是几何偏移，不是 1.5 m/s 速度假设。

“按静止预测”表示每个规划周期内固定位置；下一帧有真实检测时仍然更新框的位置。不会永久冻结 ID，也不会删除 unknown 的占据空间。

## 2. 数据流和坐标

```mermaid
flowchart LR
  A[雷达 PointCloud2] --> B[过滤地面 / 自车 / 范围]
  B --> C[XY 连通聚类 / 实测 OBB]
  C --> D[定位快照转换到 map]
  D --> E[KF 预测匹配 / 速度确认]
  E --> F[ObstacleArray]
  F --> G[10 Hz 异步规划与监督]
  G --> H[原子参考轨迹]
  H --> I[50 Hz 空间投影 / LQR / PI / 指令约束]
  F --> I
  I --> J[CarCtr 底盘指令]
```

定位输入是车体几何中心。规划、跟踪内部转换为后轴：

`rear_x = centre_x - 0.345*cos(yaw)`，`rear_y = centre_y - 0.345*sin(yaw)`。

车体长 1.2 m、宽 0.8 m、轴距 0.69 m。碰撞检查会再转回车体中心检查完整矩形。RViz 先手动定位，再手动发布目标；目标使用 map 下的 x/y，目前终点姿态没有作为需要跟踪的目标 yaw。

## 3. 感知：点云怎么变成障碍物

主要源码：`perception_core.py`、`lidar_track_node.py`、`async_perception.py`。

### 3.1 输入、过滤和地面

1. 根据 PointCloud2 的 XYZ 字段偏移、数据类型、大小端、行间距解析点云；去掉非有限值。
2. 用配置的传感器 x/y/yaw 变换到车体系；z 加雷达安装高度 0.45 m。目前只用平面定位 yaw，不做逐点运动补偿，也不根据 roll/pitch 做完整三维补偿。
3. 保留车周围 8 m 内的点，当前全周检测 `track_all_around=true`；x/y 直通范围也同时作用。当前 `front_x_min/max` 不决定全周检测的范围。
4. 去掉自车矩形中的点：长 1.2 m、宽 0.8 m，每侧外扩 0.05 m。
5. 地面用 `z = a*x + b*y + c` 拟合。选距车 0.8–4 m、z 在 −1.6 至 0.2 m 的候选点，通过 z 直方图找主峰，再做 4 轮残差/MAD 抗离群拟合。需要至少 50 点、x/y 跨度各至少 0.6 m，倾斜不超过 15°。
6. 地面小幅变化按 0.7 旧值 + 0.3 新值平滑；高度截距变化超过 0.15 m 直接采用新观测。拟合失败可复用旧地面至多 1 s；超过后该次感知无效，不发布“无障碍”的假空场景。
7. 保留离地高度 0.12–2.2 m 的点。启用地面过滤时，旧 `pass_z_min/max` 不是主要高度判断。

### 3.2 聚类和包围框

- XY 体素边长 0.10 m。每格保留 x/y 方向的四个极值代表；代表点之间使用 0.30 m 欧氏距离判断连接。
- 连接性来自 XY；不同高度但投影相近的点可能连在一起。目前不是完整 3D 语义分割。
- 代表点只用于确定连通分量。支持点数和 OBB 用全部原始支持点计算。
- 支持点少于 10 个，或长边小于 0.20 m，移除。输出长/宽最低 0.10 m。
- PCA 主轴确定框方向，再用该方向上的全部点极值包住实测点。高度目前用于过滤和诊断，不参与最终二维碰撞框。
- 连通分量长边超过 3.5 m 时，在固定 map 网格中按 1.2 m 分片。弱片段若距强片段不超过 0.30 m 就合并，否则删除。墙面、楼房边缘因此可能显示为多个框，框数不等于真实独立物体数。
- 最多允许 8000 个聚类代表点；超过返回 `cluster_capacity`，不会假装空场景。

### 3.3 “行人/自行车/汽车”名称的实际含义

它们只是尺寸提示，没有语义识别模型：

| 实测尺寸条件 | 检测提示 |
|---|---|
| 长边 ≤ 0.35 m | pedestrian |
| 长边 ≤ 0.95 m | bicycle |
| 长边 ≤ 2 m 且短边 ≤ 1.1 m | vehicle |
| 2–6 m 长边且 0.8–2.5 m 短边 | vehicle |
| 其他 | static_large |

墙片、树、路障、车辆局部点云均可能得到这些名称。跟踪器最终会结合运动确认重新发布类别。因此看到 pedestrian/vehicle 不能直接证明现场有行人/汽车。

### 3.4 感知线程与时间

感知在独立进程执行，只保留最新一个等待点云，避免积压。收到点云时取最近有效定位快照，并转换至 map；不是逐点或点云时刻严格插值的定位同步。

结果保留原始采集时间。原始数据及处理结果年龄上限都是 0.4 s。超时、地面失效等不会发布伪空场景。只有两次有效跟踪观测的时间间隔超过 2 s 才重置 KF，普通降频不会反复清空 ID。

## 4. 障碍物匹配：如何保持同一 ID

主要源码：`kf_tracker.py`。

每个轨迹的状态是 `[x,y,vx,vy]`，初速度为零。每次先按真实点云采集时间间隔 dt 做 CV 预测：`x += vx*dt`，`y += vy*dt`；再把预测中心和新检测中心匹配。

匹配需要同时满足：

1. 预测中心到检测中心欧氏距离 ≤ 1.0 m。
2. 上次真实测量中心到新中心的位移 ≤ `1.5 * 距上次测量的时间 + 0.15 + shape_slack`。

`shape_slack = min(0.35, 0.5*hypot(长边变化,短边变化))`，尺寸比较时先把长宽排序。它允许部分遮挡导致实测框中心和尺寸变化。

成本只有中心欧氏距离；尺寸用于可达门限修正，没有类别惩罚、点云外观相似度或专门的遮挡/分裂/合并模型。SciPy 可用时用匈牙利匹配；不可用时按距离从小到大贪心锁定配对。当前本机验证走贪心分支，Jetson 使用哪个分支取决于其 SciPy 环境。

匹配成功：KF 更新、miss 清零、刷新实测形状和尺寸。新检测没有匹配：创建新 ID。旧轨迹没有匹配：miss 加一，内部继续预测。连续 10 个**已处理帧**漏检后删除；20 Hz 下约 0.5 s，实际降频时保留更久。

已确认静态物体短时漏检仍按静态保留；已确认动态物体漏检会改为 unknown。本次修改后这类 unknown 也固定于最后实测位置，不再动态扩张。

## 5. 速度估计与运动确认

位置观测由 CV 卡尔曼滤波器更新。过程噪声系数 q=0.3，位置测量标准差 r=0.15 m；协方差采用 Joseph 形式更新。

速度估计：`speed = hypot(vx,vy)`，运动方向 `atan2(vy,vx)`；输出速度小于 0.05 m/s 归零，发布上限 1.5 m/s。分类计数用内部原始 KF 速度，而不是截断后的发布速度。

| 真实匹配观测的 KF 速度 | 计数行为 |
|---|---|
| > 0.30 m/s | 动态计数 +1，静态计数清零 |
| < 0.15 m/s | 静态计数 +1，动态计数清零 |
| 0.15–0.30 m/s | 两个计数都清零 |

- 连续 5 次高速度观测确认 moving。
- 连续 10 次低速度观测确认 static。
- 未达到确认条件输出 unknown。预测帧不会推进确认计数。
- moving 标志保持到连续 10 次低速度观测才取消；但 static 的确认计数并非永久锁存。一帧进入中间速度区间后，原来静态的同一 ID 可能重新输出 unknown。
- 已确认 moving 保留 pedestrian/bicycle/vehicle 尺寸提示；其他尺寸提示的 moving 默认发布 pedestrian。
- 已确认静态长边 ≤0.6 m 发布 block，否则 static_large。

现在 unknown 输出最新**实测**中心、实测框和零速度；内部 KF 仍在更新，因此以后仍能确认真实运动。确认动态/静态框的中心使用滤波位置，并加几何包络修正以包含最新实测框，这种尺寸修正与本次删除的 `1.5*age` 扩张不同。

固定建筑片段在遮挡、聚类合并/分裂、定位快照变动时会产生中心跳动。当前门限减少了错配，但不能消除所有伪速度。如果现场全静止而日志 `moving_count>0`，应继续核对连续 ID 的检测中心、实测尺寸、KF 速度和匹配过程。单纯看到动态输出不代表真实运动。

## 6. 两种预测要分开理解

**跟踪器内部预测**用于寻找下一帧属于哪个 ID，不等于规划器一定把它当成运动物体。

**规划器的障碍物预测**：

- unknown / block / static_large：`position(t) = 当前发布位置`。
- 已确认动态：`position(t) = 发布位置 + 估计速度向量 * (障碍物消息年龄 + t)`。
- `heading` 是运动方向；`shape_heading` 是物体几何框朝向。平移几何框时保持其形状朝向，避免把运动方向误当成车身/行人框朝向。
- 动态模型是 CV，不预测行人的主动让路、加速度、突然转向或自行车意图。

**小车自身预测**使用后轴自行车模型：`yaw_rate = v*tan(steer)/0.69`，积分得到 x/y/yaw；速度、转向均先经过执行器变化约束和延迟，再进入运动学。

当前运行入口是 `RealtimeAckermannPlanner.plan()`，覆盖继承的 EnhancedDWA 方法。`model_path` 必须为空，DQN 没有参与；旧 ObstaclePredictor 对象虽被构造，但当前实时主循环直接使用 TrackedObstacle，不调用旧 IMM 预测链。

## 7. 规划：每次如何选路、选速度

### 7.1 监督和引导

主监督 10 Hz，单独规划进程计算；计算预算 0.25 s，结果最大年龄 0.8 s。结果还检查目标是否改变、与已检查轨迹前段的距离是否超过 0.18 m、方向偏差是否超过 12°。沿轨迹正常前进不按初始点位移直接判失效。

静态引导使用目标对齐的坐标系。把静态及 unknown 的 OBB 变成包围 AABB，再加 `半车宽0.4 + margin0.12 + guide_extra0.12 = 0.64 m`。最多取 8 m 内最近 8 个框，若直线通行就用目标，否则在框角点构建可见性图并用 Dijkstra 找引导点。

引导点保持，距它小于 0.65 m 或可以跳过中间点时前移。它是几何启发，不是完整全局地图路径；最终候选碰撞检查仍使用全部输入障碍物（容量上限 96 个），而且检查物理矩形。

### 7.2 普通候选和动力学

采样 9 档目标速度，再加入当前速度和零；采样 17 档目标转角，再加入当前转角和零，去重后做组合。

目标速度上限 1.0 m/s，转角 ±30°，普通前视 3 s，积分步长 0.05 s。`velocity_horizon_targets=true` 时采样的是伺服目标速度，不是瞬间跳变的真实速度。

预测和控制采用相同的主要约束：加速 0.7 m/s²、减速 1.2 m/s²、jerk 2 m/s³、转向速率 30°/s、转向加速度 100°/s²、执行延迟 0.1 s，横向加速度上限 0.6 m/s²。接近目标时按剩余距离、延迟和加速度回落计算刹车速度上限。

### 7.3 碰撞和评分

车体是完整 1.2×0.8 m 有朝向矩形，障碍物是实测有朝向矩形。用分离轴距离下界检查所有轨迹时间点，减去采样间小车/已确认动态障碍物运动的扫掠界，要求间距至少 0.12 m。unknown 在整个 3 s 规划时域固定占据实测框。

主要评分：朝引导目标的距离进展×3；最终方向误差惩罚×0.3；最大预测速度奖励×0.15；间距奖励×0.15（间距奖励最多按0.4 m计算）；目标转向量惩罚×0.4；本次相对当前转向变化惩罚×0.12。

全部候选不可行：若固定障碍物本来允许运动、但已确认动态冲突排除了运动，则 dynamic_yield；否则 blocked。选择零目标速度且存在运动候选时可能 orientation_stall，监督器会处理车头与目标方向不合的问题。

### 7.4 已确认迎面物体

速度至少 0.2 m/s、在车前超过0.3 m、相对闭合速度超过0.2 m/s、对方朝小车方向的速度分量低于 −0.15 m/s、横向处于通道范围、TTC小于7 s 时，选择最紧迫的迎面目标。

锁存避让对象和左右方向，避免每帧改边；前视至少5 s，额外采样“向外转→反向回正→停车”的分段轨迹。目标速度0.45/0.7/0.95 m/s，转向阶段0.7/1.1/1.5 s，刹车起点2.4/3.2 s。终点侧方停车位置需避开动态目标未来 CV 射线；仍可行的旧分段动作优先续接。

有已确认动态物体时，还检查先执行0.4 s动作再刹车的备份，备份减速度0.8 m/s²。经过完整验证并停在侧方避让位置的分段轨迹可用续接代替“立即在行人路线上停车”的备份。

本次没有改已确认动态策略。unknown 不再触发迎面运动准备；它只按静态框绕行。

### 7.5 恢复/自转

距原目标小于3.5 m且引导方向误差大于75°，或规划停滞累计1.5 s，可请求自转。即使规划输出运动，实际位置长期没有进展（0.12 m范围内约3 s）也会进入恢复判断。

恢复先检查完整旋转车体，再检查恢复直线段；必要时设置1.8 m子目标。每次恢复最多2次重试，一个目标最多4次自转请求。控制等待静止、底盘模式反馈、机械切换等待约3 s，然后按会话锁存角度自转。失败或无安全方向会停住。

## 8. 跟踪与控制：为什么能平滑、哪里仍会突停

主要源码：`traj_tracker_core.py`、`traj_tracker_node.py`、`adaptive_preview.py`。

1. 50 Hz运行，接收原子参考：后轴x/y/yaw、目标速度、预测时间、目标转角；整条替换，不拼接旧尾段，不独立用B样条改写已验证几何。
2. 根据当前后轴在轨迹段上的最近投影得到弧长s，在空间位置s处插值参考；不是按墙钟时间追逐移动的x/y参考点。
3. 计算横向误差和方向误差，用LQR反馈。Q=(8,2)、R=4、空间离散0.1 m；横向死区0.015 m、方向死区0.7°，反馈修正最多8°，总目标转角最多30°。
4. 若参考带明确目标转角，就以该转角作前馈；否则按预瞄曲率 `atan(0.69*curvature)` 前馈。自适应预瞄仍计算，但有明确目标转角时，它对转向前馈的影响有限。
5. 预瞄根据间距、曲率、曲率变化调整。空旷时用速度×0.4 s、最多0.5 m；复杂/近障时速度×0.15 s、最多0.15 m；恢复长预瞄有0.6 s保持和增减速率。此过程不建立切角替代路径。
6. 速度上限同时受参考速度、1.0 m/s上限、横向加速度和方向误差约束。PI参数P=0.3、I=0.05，积分限幅0.1；最终目标速度不高于速度上限。D参数当前为0，代码也未使用D项。
7. 速度/转角输出通过jerk、加减速、转向速率和加速度约束。小车速度和yaw_rate由0.45 s定位窗口的二次拟合端点导数估计，使用Huber权重抑制离群；不是障碍物KF速度，也不是单帧位置差分。
8. 使用最新障碍物再次预测执行时域：至少0.8 s，或按当前速度/减速度增加；unknown仍固定，已确认动态仍CV。不通过则执行EXECUTION_GUARD停车。
9. 控制收到超时、无效输入、碰撞等停止原因时，`stop_cmd()` 会直接把速度指令置零并清积分。这些停止分支不经过正常速度jerk渐变。因此代码能限制正常行驶指令变化，但不能保证任何停车原因下都平滑，也不能仅靠软件证明真实机械无振荡。
10. 输出底盘CarCtr：ACK转向模式0，速度m/s、转角度；自转模式4，speed字段承载角速度。没有修改底盘协议。

## 9. 仍会使车停住的条件和旧参数

| 诊断原因 | 实际含义 |
|---|---|
| no_goal | 尚未接收到RViz目标 |
| obstacle_timeout | 障碍物原始数据年龄超过0.4 s |
| localization_fault / localization_timeout | 定位输入无效或有效数据超过2 s |
| planning_budget | 该次计算超过0.25 s |
| planning_result_stale | 超过0.8 s或目标/轨迹偏差失效 |
| blocked | 实测框和车体/轨迹间距不足，或没有可行运动 |
| dynamic_yield | 已确认动态占据排除了固定场景本来可行的运动 |
| orientation_stall | 目标/引导方向不适合直接前进 |
| execution_collision_guard / EXECUTION_GUARD | 新障碍物或实际状态使执行复核不通过 |
| empty_plan | 控制器收到清洗后不足2点的参考，是下游症状，须结合上游原因 |
| recovery_no_safe_heading / recovery_exhausted | 没有可验证的恢复方向或次数耗尽 |

手动定位大幅改变map坐标时，只在无目标且ACK静止条件下允许重新初始化；活动目标中的异常跳变仍拦截。最近有效定位接入没有改定位算法或TF发布器。

YAML中仍保留历史兼容参数。当前不应把APF权重、轨迹缓存/粘连、smooth_weight、fusion_len、B-spline参数、旧TrackManager/IMM设置当成实时主链已启用的算法。`cluster_max_radius`也没有作为新perception_core聚类的主范围判定；实际使用max_obstacle_range和ROI。检查“参数已生效”时需要确认它确实被当前主链使用。

## 10. 验证结果与边界
