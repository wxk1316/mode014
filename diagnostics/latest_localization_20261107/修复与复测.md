# 最近定位缓存与异步规划预算修复

本次已按要求使用最近收到的有效定位信息，并依据新实车诊断调整异步规划时间预算。RViz 手动定位和手动发布目标的流程继续使用。收到有效定位前不能规划，收到目标前保持 no_goal。

## 新实车输出确认的原因

规划诊断 t=1065.948 秒显示：

- localization_input.source=tf，reason=tf_valid，定位源年龄 0.040453 秒。
- obstacle_age_s=0.189765 秒，满足 0.4 秒障碍物门限。
- goal_received=true。
- planner.duration_s=0.095168 秒，worker_duration_s=0.095243 秒。
- 配置 planning_budget_s=0.08 秒，最终 reason=planning_budget，traj_arc_len=0。

这一帧有有效定位和障碍物信息，但完整计算超过 80 ms 上限，参考被丢弃。这已明确解释了一类当前空路径；计算异常还会冻结正常的脱困计时。

约 21 秒后的控制诊断另显示 safety_reason=planning_result_stale、reference_points=0。两条记录不是同一时刻，不能把它们拼成一个帧。后一帧说明结果有效期或状态一致性检查曾触发，但没有同时提供对应 planner.result_age_s 等字段。新代码在 stale_causes 中明确区分 result_age、goal_changed、pose_displacement、yaw_change，并保留 worker_reason，便于继续归因。

## 生产改动

| 设置 | 上一版 | 本次 |
| --- | --- | --- |
| 定位接入 | TF 源时间戳 | latest_topic，缓存最近收到的有效 /localization 位姿 |
| 定位超时 | 规划/跟踪 0.35 秒，感知 0.5 秒 | 三处统一 2.0 秒，按单调接收时钟计时 |
| 规划计算预算 | 0.08 秒 | 0.25 秒 |
| 异步结果有效期 | 硬编码 0.3 秒 | planning_result_max_age_s=0.8 秒，可配置 |
| 异步周期 | 子进程初始 params.dt | 每次请求携带当前真实 control dt |

latest_topic 接受较旧、相同或不稳定的 ROS 消息头时间戳；原始头时间戳仅保留作诊断。每次收到有效定位消息都更新缓存；周期性读取缓存不会更新接收时刻，所以真实断流超过 2 秒仍停车。坐标帧、有限值和非零四元数检查保留。

此模式将上游最新发布的有效位姿视为可用位置；接收时间本身不能证明上游传感器产生了新测量。仍采用同一车辆尺寸和坐标补偿，保留位姿跳变检查、目标一致性、0.18 m/12° 规划结果一致性门限、0.4 秒障碍物门限，以及最终命令碰撞检查。250 ms 预算在独立子进程里执行，主规划监督和控制回调不等待后台计算。

本次生产修改六个文件，路径相对现有工作空间：

- src/rda_dwa_real/rda_dwa_real/localization_input.py
- src/rda_dwa_real/rda_dwa_real/bridge_node.py
- src/rda_dwa_real/rda_dwa_real/lidar_track_node.py
- src/rda_dwa_real/rda_dwa_real/traj_tracker_node.py
- src/rda_dwa_real/rda_dwa_real/async_planner.py
- src/rda_dwa_real/config/real_vehicle.yaml

定位算法源码、TF 发布、RViz 目标接收和底盘源码没有在本次修改。源时间 topic 模式和 TF 模式作为显式配置选择保留。

## 覆盖部署

停止旧 launch，保持原定位包，将 hotfix_latest_localization_20261107.zip 放到车机现有工作空间根目录：

```bash
cd ~/Desktop/Wxk/car_gpt
unzip -o hotfix_latest_localization_20261107.zip -d .
colcon build --symlink-install --packages-select rda_dwa_real
source install/setup.bash
ros2 launch car_launch run_rda_dwa.launch.py
```

plan2 是改动文件仓库，不能单独替代完整 ROS 工作空间；使用 GitHub 时，应把这六个路径覆盖到原车机工程。

重新启动后先核对实际配置：

```bash
ros2 param get /rda_dwa_real_bridge localization_source
ros2 param get /lidar_track_node localization_source
ros2 param get /traj_tracker_node localization_source
ros2 param get /rda_dwa_real_bridge localization_timeout
ros2 param get /lidar_track_node loc_timeout
ros2 param get /traj_tracker_node localization_timeout
ros2 param get /rda_dwa_real_bridge planning_budget_s
ros2 param get /rda_dwa_real_bridge planning_result_max_age_s
```

三个 source 应为 latest_topic，三个定位超时应为 2.0，两个规划参数应为 0.25、0.8。若仍显示 tf/0.08，则旧配置仍在运行。

按原流程完成 RViz 手动定位，再发布目标。需要完整输出时使用：

```bash
ros2 topic echo /rda/diag --once --full-length
ros2 topic echo /rda/control_diag --once --full-length
```

重点看 localization_input.reason=latest_topic_valid、receive_age_s、planner.worker_reason、planner.stale_causes、reference_points 和 command.speed。若后续为 blocked/dynamic_yield，则已转入场景可行性问题，不能单凭空路径断定时间戳问题。

## 回滚

停止 launch，解压 rollback_latest_localization_20261107.zip 到同一工作空间根目录，重建 rda_dwa_real 并重新 source。六个上一版文件及 SHA256 在 before/ 和 before_sha256.json 中保留。
