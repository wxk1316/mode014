# 斜行模式接入与切换优化方案

日期：2026-11-08。范围：设计建议；未修改运行代码、未连接实车。

依据：用户提供的《三模式控制接口说明(1).md》及当前工作空间源码。接口文档中的示例、建议和“必须”条目作为底盘行为描述与待核实约束，不视为执行实车指令的授权。反馈报文的标称 25 Hz 不代表实际频率稳定，也不代表报文内每个字段都刚从硬件更新。

## 1. 推荐架构

采用“规划侧选择运动模式，跟踪侧执行模式专用控制器，驱动侧独占底盘切换事务”的分工。

| 层级 | 职责 | 建议改动位置 |
| --- | --- | --- |
| 局部规划 | 采样 ACK/CRAB 的受约束轨迹；SPIN 用少量恢复/对准运动基元；比较完整动作时间和安全性 | `rda_dwa/realtime_ackermann.py`，新增 `crab_model.py`/`multimode_planner.py` |
| 模式监督 | 根据候选成本、当前模式、反馈质量与任务选择模式，锁存目标，抑制频繁切换 | `rda_dwa_real/realtime_vehicle_core.py` |
| 轨迹跟踪 | ACK 保留现有控制器；CRAB 独立位置跟踪；SPIN 保留航向控制；停车并提交切换请求 | `rda_dwa_real/traj_tracker_core.py` |
| 计划消息 | 原子携带轨迹、模式、序号、有效期及参考点，避免模式与路径错配 | `rda_dwa_real/bridge_node.py`、`traj_tracker_node.py` |
| 底盘驱动 | 串行发送、停止与角度复位、模式回显确认、机械到位判定、超时与反馈年龄 | `control/car_ctr/src/car_ctr.cpp` |

不在跟踪器里仅凭某个横向误差阈值临时改模式。这样会使规划器按 ACK 预测出的轨迹与实际 CRAB 运动不一致；切换等待及动态障碍物也未进入预测。跟踪器可以拒绝不安全计划、请求重新规划，但模式战略选择保持唯一来源。

## 2. 明确三种运动学和消息语义

底盘编号为 ACK=0、CRAB=1、SPIN=4。当前规划协议的 `mode=1` 表示 SPIN 请求，与底盘 CRAB=1 冲突。建议发布协议 v2，使用 `motion_mode: ACK|CRAB|SPIN`，只在驱动适配层映射为数字。迁移时保留旧协议解释，禁止直接把旧 `mode=1` 改成斜行。

建议计划字段：`schema_version, plan_seq, session_id, motion_mode, reference_frame, reference_point, valid_for_s, theta_ref, points`。轨迹点显式包含 `t_rel, x, y, body_yaw, path_speed, beta`；ACK 可以有 `steer`，SPIN 可以有 `omega`。同一条原子计划不能混用不同模式的字段含义。等待中的计划只作为意图，READY 后须基于最新位姿和障碍重新生成可执行轨迹。

斜行理想模型（世界坐标，β 为经过标定的实际平移方向与车头夹角）：

```text
dx/dt = v*cos(theta + beta)
dy/dt = v*sin(theta + beta)
dtheta/dt = 0
vx_body = v*cos(beta)
vy_body = v*sin(beta)
```

v 是沿车轮方向的速度，β 上限为 30°，不是自由横向速度。首版可按 20°、0.3 m/s 的保守运行限值接入，再依据实测放开；角度变化率不得超过接口的 45°/s，当前软件较低的限制可以继续沿用。采样必须积分实际角度变化与加减速，不能瞬时实现目标 β。

首版只使用前进斜行，避免同时引入倒车的角度等价、符号和安全范围改动。若后续支持倒车，使用带符号 v，分别处理前进/倒退可行锥；不能对全部速度向量直接使用正向 `atan2`。

以车头沿世界 x 轴、β=30° 为例：横向移动 0.30 m 至少需要前进 0.30/tan(30°)=0.52 m，总平移距离 0.60 m。v=0.30 m/s 时匀速运动需 2 s。如果动作要求 ACK→CRAB→ACK，则切换就需 6 s，理想总时间至少 8 s，尚未计入制动、角度复位、摆角和加速。首版限 20° 时所需前进空间更大。

若目标需要改变车体航向，斜行本身不能完成。路径切线 `atan2(dy,dx)` 与 `body_yaw` 在 CRAB 中不同，不能用切线覆盖车体航向。路径位置可以弯曲，但航向保持近似常量，且每点平移方向都要落在车头 ±β_max 的可行锥内。

目前代码采用后轴中心规划、几何中心定位和自转。可以保留这个约定并在各模式模型入口/出口做一致转换，不必一次重写全部坐标。碰撞始终按实际车体矩形评估；0.51 m 轮距不是当前配置 0.8 m 的车体外宽。ACK 的名义曲率和 SPIN 的轮速到角速度映射均需实车标定，不能把接口表格中的工程估算当精确模型。

## 3. 在规划中显式计入切换成本

当前局部预测一般为 3 s；进入别的模式本身就需 3 s。若只在这段时域比较位移，新模式尚未开始运动，因此难以得到有意义的比较。

建议使用两级评估：

1. 当前模式继续使用现有短时域与实时预算，做密集采样及执行安全检查。
2. 模式选择使用少量完整动作候选，包含“制动→复位→切换等待→新模式运动→必要时退出”。可评估约 8～12 s 的任务动作，或用动作运动时间加终端代价；不需要把所有 DWA 采样都扩大为长时域。

所有候选先满足碰撞、停止空间、方向锥及任务航向条件，再比较成本。不能仅比较几何路长。

```text
J = w_time*(T_motion + sum(T_transition))
    + w_path*path_error + w_heading*task_heading_error
    + w_input*input_variation + w_uncertainty*state_uncertainty
    + w_switch*N_switch

T_transition = T_brake + T_zero_state + T_handshake
               + T_wait + T_prepare_target
首版 T_wait >= 3 s，按当前驱动的等待起点定义计时。
```

等待期间车辆位置近似不变，但动态障碍继续运动。整个制动/等待/执行时间轴必须进入动态碰撞评估，等待点也必须安全。长时域匀速障碍预测只是候选评估，不能承诺 12 s 后安全；执行持续以新观测复核，预测不确定时等待或取消，并保留停车余地。

CRAB 采样输入为 `(v,beta)`，不能把它伪装成现有 `(v,omega)` 后再通过 `atan(omega*L/v)` 解算。ACK 与 CRAB 的路径朝向评价也不同：CRAB 的运动方向应朝向局部通行方向，车体航向则按任务需要保留；当前 `realtime_ackermann.py` 中对目标方向与车体航向之差的惩罚不能原样复制。

模式选择原则：

- ACK：长距离巡航、持续需要改航向、已有轨迹顺畅时默认保持。
- CRAB：航向已合适、需要持续横向调整、方向锥与前进空间允许，而且完整动作胜过 ACK 时采用。
- SPIN：需要较大航向调整或恢复，并且旋转扫掠和后续运动均可行时采用。
- 动态目标近距离接近：先比较当前模式制动/避让的时机；不能把耗时 3 s 的切换当作瞬时逃避动作。
- 已处于 CRAB 且后面是直路：β→0 继续走即可，不强制立即回 ACK。只有后续需要改航向或其他约束要求时退出。
- CRAB 无法通行时继续比较其他候选，不能直接认定已脱困，也不保证任何死胡同都有解。

## 4. 模式切换状态机

每个底盘切换事务拥有递增 session_id、固定源模式和目标模式；普通新计划不能反复改变进行中的目标。故障/急停优先级最高，可以中止事务，保持当前机械模式下的零驱动；禁止自动摆轮“回默认模式”作为故障处理。

```text
RUN(source)
  -> BRAKE(source, 保持当前摆角)
  -> STOP_CONFIRMED
  -> ZERO_STATE(速度为0，将输入a复位0)
  -> REQUEST(target，发送一次模式指令)
  -> WAIT_ECHO(必要时受控重试)
  -> WAIT_MECHANICAL(首版至少3s)
  -> PREPARE_TARGET(零速设置目标beta/steer)
  -> READY(target, session)
  -> REPLAN_FROM_CURRENT_STATE
  -> RUN(target)

任意阶段：反馈失效/控制权丢失/故障/等待点不安全 -> ZERO_DRIVE / FAULT
```

注意 BRAKE 和 ZERO_STATE 分开：仍在运动时贸然回正会改变停车轨迹，应先按受约束制动停车。模式 4 的 `a` 不决定物理轮角，`Run 0 0` 只能处理内部角度状态，四轮不会因此从自转固定角回到 0。进入 0/1 后才检查其目标轮角。0/1→0/1 可在 a=0 的共同轮位上切；初版仍遵守 3 s，之后才考虑缩短。

串行发送器单独按稳定周期运行，控制器回调只提交“期望状态”。一次报文仅一条命令。不同命令之间依据接口预留 ≥80 ms；模式指令前后安排独占时隙，避免被紧随的 `Run 0 0` 覆盖。常规运动可按接口建议的 25 Hz 连续更新同一种 `Run`。重发采用同一 session；有效匹配回显到达后不再反复发模式指令。重试不无限延长整个事务的截止时间。

驱动发布 `mode_state: REQUESTED|ECHOED|READY|FAULT`、`session_id`、`actual_mode`、`requested_mode`、反馈年龄和失败原因。跟踪器等待 READY，不再自己猜测一个独立的 3 s 到位时间。现有驱动与跟踪器两组 3 s 计时可能重叠，并非必然相加为 6 s；统一完成信号主要用于消除计时起点不一致和边界竞争。

## 5. 不稳定反馈的处理

到位判定和运行状态估计需要不同反馈，不能让不稳定 UDP 回包驱动控制循环频率。定位/跟踪使用各自稳定定时器，异步回包只更新有年龄、有有效标志的状态缓存。

| 证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `turnmode` 回显 | 底层接受/设置了该模式编号 | 四轮机械到位 |
| `Active`、`errcode` | 使能/诊断状态，且有各自延迟 | 车辆已经停止或转角已经到位 |
| `Wheel speed` | 取决于固件字段来源；可能仅是给定回显 | 在未核实之前不能证明实际轮速为零 |
| `Turn pos` | 仅在标定、随动、硬件分支有效且新鲜时反映角度 | 常零或缓存值不能作到位证据 |
| 定位/IMU | 车体平移/横摆及是否停止 | 静止时不能证明四轮摆角到位 |

STOP_CONFIRMED 使用新鲜定位/IMU的平移模长 `hypot(vx_body,vy_body)` 与角速度，并要求持续静止；若有真实轮速可作为额外证据。不能把没有反馈等价为“已经停车”。如果定位无有效速度估计窗口，也应标记未知，而非以初始化的 0 通过检查。

有可信角度反馈时，机械检查可采用全部四轮与各自目标的误差 ≤ε（例如先用 2°作为联调值）并持续约 0.2～0.3 s。角度偏置、单位、轮索引与目标符号必须先标定。一次满足不足以完成判定；同一缓存值被重复发布也不能累计成多次新观测。

首版仍保持 3 s，即使可信角度提前满足也不提前放行。以后经实测允许缩短时，可定义：

```text
READY = 新鲜且属于本次事务的目标模式回显
        && 控制权及使能有效
        && 没有阻止运行的故障
        && STOP_CONFIRMED
        && 全部目标轮角有效、到位、保持
        && 达到该模式转换的经标定最短等待
```

没有可信角度时：使用保守等待与有限超时；先完成上位机方案但不缩短 3 s。定时结束只是开环估计，不是机械确认。模式回显或其他必要反馈完全丢失时，即使已经等满 3 s 也不启动。若要严谨提供 READY，优先补固件实际编码器、目标角、驱动新样本序号/采样时间和 busy/ready。

分别记录 `t_rx`（真正收包）、`t_parse`、各字段最近更新、固件数据采样年龄、源序号。包到达时间不能替代编码器数据年龄；旧状态重新发布不能更新有效时间。无底层源时间/序号时，明确表示字段新鲜度未知，不能通过多个相同包推断新采样。

通过日志统计间隔分位数以配置告警/重试节奏；安全硬超时必须受实际停车能力及通信风险限制，不能随越来越差的频率无限放宽。固件断链保持末值意味着上位机发送停车在物理断链时可能无法生效，必须由底层超时清驱动/独立急停补齐。建议同时修复覆盖式接收队列，并确保障碍停车保护覆盖 CRAB 和 SPIN；文档中的 `Scan_Stop` 只覆盖 ACK 前进。

## 6. 斜行专用跟踪控制器

保留当前 ACK LQR。CRAB 采用位置速度前馈与横向/纵向误差反馈：

```text
u_world = p_dot_ref - K_position*(p - p_ref)
u_body = R(-theta_measured)*u_world
将u_body投影到前进CRAB可行锥、速度与加速度约束
v_cmd = hypot(u_body.x, u_body.y)
beta_cmd = atan2(u_body.y, u_body.x)
再施加beta幅值/变化率限制，并用同一约束模型验证实际可执行轨迹
```

若向量模长接近零，保持或有计划地复位摆角，不在 atan2 的近零噪声下跳变。到目标时减速停车。CRAB 不能独立控制横摆，因此航向误差只能监测，无法像全向底盘一样同时自由给定 vx、vy、omega。持续超出允许航向偏差时反馈给规划监督器重新选择模式。

安全预测必须使用实际限速后的 beta 和 v，处理启动摆角、制动距离与动态障碍。当前跟踪/监督的 ACK `rollout_rear` 不能复用于 CRAB；新增模型应贯穿候选预测、参考生成、跟踪预测和停车验证。学习/控制参数不要仅通过复制 ACK LQR 获取。

## 7. 当前代码的接入前问题与具体挂点

1. `control/car_ctr/src/car_ctr.cpp:37,218`：驱动固定 3 s；`traj_tracker_core.py:43,244,282`：跟踪又自己计时。改为驱动统一事务完成信号，首版保留等待下限。
2. `traj_tracker_node.py:207`：只接收旧规划 mode 0/1；`traj_tracker_core.py:108`：仅 ACK 接收轨迹；`realtime_vehicle_core.py:100`：输出模式是自转请求布尔值。都要升级为显式三模式协议。
3. `realtime_vehicle_core.py:160`：非 ACK 的跟踪模式被当成返回等待，加入 CRAB 后必须区分“正常CRAB运行”和“机械切换中”。
4. `realtime_ackermann.py:218`：目标方向与车体 yaw 的惩罚适用于现有 ACK，CRAB 要分离路径方向与任务航向。
5. `pose_velocity.py:38`：只返回车头纵向投影及横摆率，丢弃侧向速度。加入 body vx/vy、速度模长和有效性，统一斜行速度控制与停车判断。
6. `CarState.msg` 无转向位置、源时间/有效性，注释中的模式编号仍与接口冲突。驱动虽已按原始编号比较，但应修正注释，新增版本化反馈，接入四轮角度与年龄。不能假设重新编译当前消息就能获得原本未上报的硬件数据。
7. `control/car_ctr/src/car_ctr.cpp:388`：轮反馈乘 `RPM2SPD≈0.0125664`，但新文档声明已是 m/s；若文档适用于当前固件，0.5 m/s 会被解析成约0.0063 m/s，影响停稳判断。对照原始 UDP、固件生产字段和实测先确认，随后修正单位或用明确版本适配，避免盲目删除换算。
8. `control/car_ctr/src/car_ctr.cpp:146`：上位角度先取负，固件也存在符号链。CRAB 用同样转换前须实测左右斜行方向，不直接认定 beta 的符号等于报文 a。
9. `control/car_ctr/src/car_ctr.cpp:156,188`：同回调可能先发零速再发切模式，间隔不足80 ms，底层可能覆盖停车命令。改为独立串行事务发送器。
10. `control/car_ctr/src/car_ctr.cpp:89` 明示实际转角不可用，接收解析中没有 `TurnN`。新增解析还必须核查固件 pos 常零的硬件分支；IMU不能替代静止时的轮角反馈。
11. 跟踪的 `set_mode_ready` 当前保存模式回显事件时间，不能代表每次最新有效反馈时间；新增独立的事件起点和更新年龄字段。
12. 当前运行 CMake 构建的是 `control/car_ctr/src/car_ctr.cpp`。根目录另有 `src/car_ctr.cpp`，实现改动应以实际构建入口为准。

接口第3节 `Disable` 附带的“改控制模式前必须失能”与第8节直接转向模式切换流程存在歧义。实施时需核查该限制是否针对电机位置/速度工作模式，还是也针对 `SteerModeCtrl`；不能未经核实就将 Disable/Enable 加入每次切换。失能在文档中是自由状态而非抱闸，若确实必须失能，还要纳入车辆保持与额外时间成本。

## 8. 落地顺序与验收

第一阶段：先修接口单位、符号、串行发送和反馈有效性；新增CRAB模型、控制器和协议；所有跨模式切换继续至少3 s。用明确场景验证行为，暂不缩短等待。

第二阶段：完整动作成本、滞回与模式保持。可用“新模式比当前节省约1 s且连续约0.5 s成立”作初始联调门槛；这些是建议初值，不是实车已验证参数。最小保持时长/距离只约束普通切换，不能覆盖急停、故障或任务已完成。比较必须包括退出模式成本，并定期重新评估，避免固定保持造成被困。

第三阶段：补可靠轮角与底层ready，实测各个有向转换，在保留硬超时的同时减少等待。模式0↔1在共同轮位a=0时潜力较大；涉及4的转换仍由驱动实际摆角过程和可靠反馈决定。接口所写“58.74°/45°/s≈1.3 s”不能证明自转转向驱动器的真实最快/最慢到位时间，因为文档也说明模式4没有此45°/s软件斜坡。

验收至少覆盖：

- 三模式有向转换全部六条，不同初始角、重复请求、切换中改目标、中止、超时。
- 原始UDP间隔检查：无停车/模式/使能覆盖，重试不会反复清零总计时。
- 反馈延迟、乱序、缺字段、整包旧缓存、pos常零、断反馈、实际轮速与给定回显差异。
- 航向固定的连续避障、短距离偏移不值得切换、斜行后直行不立即回ACK、真正需要改航向时退出。
- 动态目标在3 s等待中接近，等待位置不安全、READY后旧轨迹作废。
- 全车矩形的前后角碰撞、制动停稳、方向与速度单位标定、失联停车。

指标使用完整任务耗时、切换次数、等待耗时、最小间距、跟踪/航向误差、模式成功率和超时率。只有规划线更短不足以判定改进。

后续更长距离的三模式联合搜索可以使用含模式状态的运动基元/状态格框架；Nav2 的 State Lattice 官方介绍提供了基于自定义控制集和运动基元的参考，当前工程不必为接入CRAB整体替换现有DWA：<https://docs.ros.org/en/ros2_packages/kilted/api/nav2_smac_planner/>。
